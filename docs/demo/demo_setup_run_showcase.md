# RTSA Demo Guide — Setup, Run, and Showcase (Start to Finish)

> **Audience**: New users and presenters
> **Goal**: Run a reliable RTSA demo with minimal setup friction and a clear storytelling flow.

## 1) What this guide gives you

- A **from‑scratch setup path** (manual + automated)
- A **one‑command demo launcher**
- A **storybook‑like presenter script** so the demo is engaging and easy to follow

## 2) Prerequisites (manual checks)

1. Install Docker and ensure daemon is running.
2. Install Go and Node prerequisites by following the getting started docs.
3. Clone the repository:

```bash
git clone https://github.com/arvinddhasmana/RTSA_VS_Opus.git
cd RTSA_VS_Opus
```

## 3) Automation path (recommended)

### 3.1 Optional first‑time environment setup

```bash
bash scripts/setup/setup-dev.sh
```

### 3.2 Quick‑Start Commands

| Scenario | Command |
|----------|---------|
| Maritime Demo | `bash scripts/demo/run-demo.sh maritime` |
| Multi‑Domain Demo | `bash scripts/demo/run-demo.sh multi-domain` |
| Stop Live Feed Only | `bash scripts/demo/stop-demo.sh --live-feed` |
| Stop All Containers | `bash scripts/demo/stop-demo.sh --containers` |
| Stop All + Remove Volumes | `bash scripts/demo/stop-demo.sh --volumes` |

### 3.3 Run the primary demo (maritime)

```bash
bash scripts/demo/run-demo.sh maritime
```

### 3.4 Run the secondary demo (multi‑domain)

```bash
bash scripts/demo/run-demo.sh multi-domain
```

### 3.5 Stop and clean everything

```bash
bash scripts/demo/stop-demo.sh --volumes
```

## 4) Manual path (if you need full control)

1. Start platform and services:

```bash
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.services.yml up -d --wait
```

2. Initialize platform dependencies:

```bash
bash scripts/dev/init-topics.sh
bash scripts/dev/init-clickhouse.sh
```

3. Run health checks:

```bash
bash scripts/dev/health-check.sh
```

4. Run a scenario:

```bash
bash scripts/demo/run-maritime-demo.sh   # or
bash scripts/demo/run-multi-domain-demo.sh
```

5. Stop stack when done:

```bash
bash scripts/demo/stop-demo.sh --volumes
```

## 6) Presenter checklist (quick success guardrails)

- [ ] Docker daemon is up before demo start
- [ ] `bash scripts/dev/health-check.sh` shows core services reachable
- [ ] Primary scenario (`maritime`) runs first
- [ ] Secondary scenario (`multi-domain`) reserved for advanced walkthrough
- [ ] Cleanup command prepared in a separate terminal: `bash scripts/demo/stop-demo.sh --volumes`

## 7) Troubleshooting shortcuts

- If setup tooling is missing: rerun `bash scripts/setup/setup-dev.sh`
- If infra did not fully start: rerun `docker compose ... up -d --wait`
- If topics/schema are missing: rerun init scripts in section 4.2
- If demo needs reset: run `bash scripts/demo/stop-demo.sh --volumes` then launch again
